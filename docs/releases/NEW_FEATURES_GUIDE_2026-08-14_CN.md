# Sub2API Plus 新功能使用说明

适用版本：`0.2.11+`

> 本指南描述技术预览功能，不代表生产可用性保证。只在隔离环境使用合成或可丢弃账户验证，并先阅读[完整风险声明](../legal/admin-compliance.zh.md)。

## 1. OpenAI/Codex 账户准备

1. 进入“管理后台 -> 账户管理”。
2. 新建或编辑 OpenAI 账户。
3. OAuth 账户填写有效凭据；API Key 账户填写 Key 和上游基础地址。
4. 如需固定出口，在“代理”字段绑定该账户使用的代理 IP；不设置 `proxy_id` 时保持原有直连行为。
5. 保存后先选择该账户执行“测活”或“一键盘点”。

OpenAI 账户未配置 `proxy_id` 时保持原有直连行为。绑定代理后，模型请求、OAuth 刷新、额度查询、盘点、测活和 WebSocket 都固定走该代理；代理被删除、ID 错配或 URL 为空时，请先修复配置，系统不会静默改为本机直连。

## 2. 一键盘点

1. 在账户列表勾选需要检查的账户。
2. 点击批量操作栏的“一键盘点”。
3. 等待结果弹窗完成，查看健康、失败、跳过、额度已获取四项汇总。
4. 在明细中查看 Credit、美元参考值、重置次数、5 小时用量、7 天用量和失败原因。

规则说明：

- 只盘点当前明确勾选的账户，不会自动扫描全部账户。
- 会覆盖全部已选择账户；前端每批发送 200 个，后端每批并发检查 8 个。
- OpenAI OAuth 使用 `/backend-api/wham/usage` 查询额度，并额外确认重置次数接口。
- 每个失败查询会再试一次，连续两次失败才进入失败结果。
- OpenAI API Key 只做真实连接测活，没有 ChatGPT Credit 数据。
- Credit 的美元金额仅为前端参考换算：`Credit / 25`，不代表账单结算金额。

## 3. 测活与失败池

1. 勾选账户后点击“测活”。
2. OAuth 账户检查额度与重置次数；API Key 账户发送真实上游连接测试。
3. 连续两次失败的账户会出现在列表上方“测活失败池”。
4. 根据失败原因更新代理、OAuth 凭据或 API Key，然后重新测活。
5. 修复并测活成功后，账户会恢复健康快照；失败池也可手动关闭。

测活失败快照会保存到账户扩展数据中，因此刷新页面后仍可显示失败状态。Claude/CC 等不支持此 OpenAI 测活模式的账户显示为“跳过”。

## 4. 奸商模式（卡429开关）

入口：

- 新建 OpenAI OAuth 账户。
- 编辑 OpenAI OAuth 账户。
- 勾选账户后使用“批量编辑”。
- “更多 -> 导入数据”。

默认关闭。显式开启后，普通 Codex 请求的历史末尾会加入一组成对的合成工具调用和响应，帮助上游保持 Agent 工具上下文；确认两次 429 后会优先保留仍健康的旧连接，连接出现读写、心跳或协议异常时才切换账户。该工具不会加入请求的 `tools` 列表。该模式可能影响客户体验和上游风控，请按账户逐一评估。

注入形态与参考项目一致：调用 ID 为随机 `call_sub2api_overdraft_*`，只有 `input` 最后一项严格为用户消息（`type=message`、`role=user`）时才会追加。Responses WebSocket 的 `input` 可以是字符串、单对象或数组，字符串和单对象会先按 Responses 语义归一为消息数组。

以下情况不会注入：

- Claude Code/Claude 渠道。
- Claude Messages 到 Responses 的桥接请求。
- compact 请求。
- 历史末尾已经是真实工具调用或工具响应。
- 历史末尾是 assistant 消息或其他非用户消息。
- 历史中已经存在本系统生成的成对上下文。
- OpenAI Shadow/Spark 影子账户。

关闭开关后，该 OpenAI OAuth 账户保持原始请求历史。此开关与上游真实 429 的账户冷却是两层逻辑：同一 OpenAI OAuth 账户仍需在 30 秒内明确收到两次上游 429，才会写入账户级限流。

## 5. Credit 与 429 状态

- Credit 来源是 ChatGPT 上游响应的 `credits.balance`。
- 有可用 Credit 时，本地额度阈值不会仅因订阅窗口用量高而自动把账户停调。
- 第一次真实 429 只触发当前请求切换账户，不污染后续调度。
- 第二次明确 429 才进入账户冷却。
- 一次成功请求会清空该账户尚未确认的 429 计数。
- 多实例部署时计数由 Redis 共享，因此两次 429 落到不同实例仍能完成确认。

如果界面没有 Credit 数据，先确认账户类型为 OpenAI OAuth、OAuth 凭据有效、代理可用，然后重新执行盘点。API Key 账户没有该字段属于正常情况。

## 6. 批量编辑、导入与更新 Key

批量编辑：

1. 在账户列表勾选同类账户。
2. 点击“编辑”。
3. 仅修改需要同步的字段，设置代理和“奸商模式”后提交。

导入数据模型账户：

1. 打开“更多 -> 导入数据”。
2. 选择一个或多个支持的 JSON 文件；代理和账户可按任意顺序出现，备用代理引用会在全部代理创建后解析。
3. 按需设置“奸商模式”（默认关闭）。
4. 导入后为账户绑定代理，再执行盘点。

导入开关只作用于 OpenAI OAuth。OpenAI API Key、Claude 和 Antigravity 数据不会被附加该字段。

代理和账户备份中的 `proxy_key` 使用 `sha256:` 摘要，不再把代理密码拼进关联键。旧版本导出的明文拼接键仍可导入；重新导出后会自动使用新格式。主代理引用的备用代理会随账户备份一并导出，导入顺序不影响多级备用链恢复。若备用代理引用缺失或 `fallback_mode` 不是 `none`、`proxy`、`direct`，该代理会明确失败，不会静默生成不完整关系。

更新 API Key：编辑对应 OpenAI API Key 账户，替换 Key 后保存，再执行测活。测活会使用更新后的 Key、基础地址、模型映射和绑定代理。

## 7. 调度行为

OpenAI 调度会优先复用正在工作且仍有并发余量的账户，尽量在容量范围内打满少量账户；需求超过当前账户容量后，再启用更多账户。这样可减少低流量下账户来回切换，同时保留以下约束：

- 账户优先级仍是首要排序条件。
- 不会超过账户并发上限。
- 账户进入冷却、测活失败或健康恶化时会被跳过。
- 粘性会话在健康正常时继续保持，异常时允许逃逸。

建议为每个账户填写真实可承受的并发数。并发值过大可能让少量账户承受过多上游压力；过小则会更早启用更多账户。

## 8. Antigravity/反代上游

创建 Antigravity 上游账户时：

1. `base_url` 可填写上游根地址、带 `/v1` 的地址，或完整 `/v1/messages` 地址。
2. 填写上游 API Key 和所需模型映射。
3. 绑定固定代理。
4. 先同步模型或执行账户测试，再从 Claude Code 客户端发起流式请求。

系统会避免重复拼接 `/v1/messages`，并兼容常见 Anthropic Bearer 与 `x-api-key` 鉴权头。CC 渠道不会启用卡429注入。

## 9. 常见排查

- 提示代理不可用：检查账户的代理记录是否存在、代理 ID 是否一致、代理 URL 是否完整。
- 盘点连续两次失败：查看失败池原因，重点检查 OAuth 过期、代理连通性和上游重置次数接口。
- 只有 API Key 没有 Credit：这是预期行为，API Key 盘点只做连接测活。
- 反代地址 404：确认 `base_url` 没有填到模型名或其他业务路径；根地址、`/v1`、`/v1/messages` 均可。
- 首个 429 后账户仍可调度：这是预期行为；同一账户的第二个明确 429 才会进入冷却。

## 10. 0.2.12 新增的官方功能

- **生图结果 URL 转 base64**：在 OpenAI 账户新建/编辑的图片配置中开启。只处理非流式 Images 响应中缺少 b64_json 的 URL 项；客户端指定 response_format=url 时不转换。下载失败保留原 URL，已绑定代理不可用时不直连下载。不要为转换功能放开私网访问限制。
- **上游请求 ID**：账户可填写上游实际使用的响应头名称，用于用量记录中的上游请求关联。该字段填头名称，不填 API Key 或完整请求头内容。
- **Codex 模型清单**：在 OpenAI 分组设置中配置 pinned-accounts 模型清单策略，并选择用于生成清单的账户。同步模型后检查展示的能力；清单展示不等于该账户有可用额度。
- **ultrafast / Astra**：先同步上游模型能力，再按客户端与上游的实际支持情况选择模型及服务档位。计价与分组 Fast/推理策略仍需管理员核对，不应把模型可见性当成上游授权保证。
- **1 小时缓存写入价格**：渠道基础价和 token 区间价可独立配置 cache_write_1h_price。显式零值会保留，不会被普通缓存写入价格覆盖。

账户列表现在自动使用保留 status/extra/runtime 的 compact DTO；不需要手工开关。界面若更新后仍显示旧字段，请先确认前后端来自同一发布版本，再清理浏览器旧资源缓存。
